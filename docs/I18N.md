# Weekra internationalization UI contract

Weekra treats localization as a layout input from the first day of development.
English is the source language, Simplified Chinese is a production language,
and `en_XA` is the development pseudo-locale.

## Required implementation rules

- All product copy belongs in `lib/l10n/*.arb`; user-created calendar content
  remains untouched.
- Text width must not be chosen to fit one language. Prefer content sizing,
  `Flexible`, `Expanded`, wrapping, and constraints derived from available
  space or measured content.
- Every bounded text region must deliberately choose expansion, wrapping,
  scaling, or ellipsis. Font shrinking is not a translation strategy.
- Layouts must tolerate at least 30–50% copy expansion.
- Text styles should define suitable line height where mixed Latin and CJK font
  metrics could change vertical rhythm. Do not align unrelated text by an
  assumed baseline.
- Use `EdgeInsetsDirectional`, `AlignmentDirectional`, `BorderDirectional`,
  `PositionedDirectional`, and start/end alignment for directional UI.
- Test new or changed screens at 320×568, with `TextScaler.linear(1.6)`, and
  with `Locale('en', 'XA')` before merging.

## Adding or changing copy

1. Add the message and placeholder metadata to `app_en.arb`.
2. Add the Simplified Chinese translation to `app_zh.arb`.
3. Add an expanded, bracketed version to `app_en_XA.arb`.
4. Run `flutter gen-l10n`, `flutter analyze`, and `flutter test`.

Use the expanded pseudo-locale while building a screen:

```bash
flutter run --dart-define=WEEKRA_LOCALE=en_XA
```

The generated `AppLocalizations` class is the only source for interface copy.
Material dates, times, dialogs, and text direction come from Flutter's locale
delegates so system preferences remain authoritative.
